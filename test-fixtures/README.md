# test-fixtures

Anonymized `draft_content.json` fixtures for the `capcut-cli-david` test suite.
Each fixture is a real CapCut draft scrubbed of personal data (paths, user names,
caption text, UUIDs) while keeping every structural and parametric field intact.

Pipeline:

```text
raw CapCut draft  →  anonymize.py  →  fixtures/<name>.json
```

The `_analyze.py` and `_inspect_fields.py` helpers in this folder were used to
profile the source drafts and design the scrubbing rules. They are local tools,
not shipped with the CLI.

## anonymize.py

Deterministic, idempotent anonymizer. See the module docstring for the full
contract — short version:

- All UUIDs are remapped through `uuid5(NAMESPACE_OID, "<fixture-name>:<orig>")`.
  Same input UUID always produces the same output UUID for a given fixture
  name, so cross-references in `tracks[].segments[].material_id`, every
  `extra_material_refs[]`, and every `graphID` survive intact.
- Windows user paths are rewritten to `/fixtures/...`. Effect-cache and font
  paths preserve the catalogue ID / filename portion (these are structural).
- Caption text is replaced with `LOREM ...` tokens at roughly the original
  length. Style ranges, fonts, colors, and the `content` JSON shape are kept.
- Catalogue names (`Fade In`, `Bounce Out`, `VHS Horror`, `渐隐`, `CC-DerStil`)
  are preserved — they are identifiers in the CapCut effect/animation library.
- `verify_fixture()` checks the result post-scrub: no personal markers remain,
  every `material_id` in a segment resolves to a material in the bundle.

Run on every mapped source draft:

```bash
python anonymize.py --all
```

Run on a single draft:

```bash
python anonymize.py <input> <output> --name <fixture-slug>
```

Flags:

- `--preserve-text`  keep the original caption text (e.g., when debugging a
  test failure where text content matters).
- `--out-dir`        override the output directory used by `--all`.

To add a new fixture, append an entry to `FIXTURE_MAP` in `anonymize.py` and
re-run `--all`.

### `animations-draft.json` — material_animations + keyword-highlight text

| | |
|---|---|
| **Size** | 25 kb |
| **Duration** | 5 s |
| **CapCut version** | 169.0.0 |
| **Tracks** | 1 video, 1 text |
| **Materials** | 1 video, 1 text, 1 `material_animations` |
| **Features** | text `material_animations` (Fade In + Fade Out), 3-style keyword highlight |

A 5-second CapCut-UI capture used to resolve Point 1b Q5. The single text segment
carries three contiguous style ranges over `"THE EYES ARE WATCHING ME."` —
`[0,13]` white, `[13,21]` purple `[0.549, 0.423, 1.0]`, `[21,25]` white. The
mid-range purple style is the canonical encoding of **keyword highlight**
(non-overlapping consecutive ranges, full styling block per range, NO partial
inheritance). The `material_animations` entry holds `Fade In` (in, 500ms) +
`Fade Out` (out, 500ms) as the canonical "text animations" reference.

> **Exception to the LOREM policy.** This fixture keeps its real caption text
> (`"THE EYES ARE WATCHING ME."`, public song lyric — not private data) on
> purpose: it is the keyword-highlight **oracle**, and the style `range` offsets
> are only meaningful against the actual text they slice. The generic LOREM
> scrubber (`anonymize.py`) replaces text at *approximate* length and leaves
> ranges untouched, which silently desyncs `range`↔text (sum of ranges ≠ text
> length). Do **not** re-anonymize this fixture's caption text.

Test cases:

- `set-text` / `set-style` with a keyword color argument — must emit the
  3-range encoding when keyword is mid-text.
- Parsing the nested `content` JSON's `styles[].range` and `styles[].fill.content.solid.color`.
- Round-trip a text segment carrying both Fade animation refs AND
  multi-range styling — no field collapse.

### `transitions-draft.json` — Dissolve between two clips

| | |
|---|---|
| **Size** | 25 kb |
| **Duration** | 10 s |
| **CapCut version** | 169.0.0 |
| **Tracks** | 1 video (2 segments) |
| **Materials** | 2 videos, 1 transition (Dissolve, 466ms) |
| **Features** | `materials.transitions[]`, outgoing-segment binding via `extra_material_refs[2]` |

A 10-second capture used to resolve Q2. Two image clips on a single video
track with a `Dissolve` transition (`duration: 466666` μs, ~0.5s) between
them. The transition material's id appears at **index 2** of the OUTGOING

- Detect transitions when reading: scan each segment's `extra_material_refs`
  for an id resolving to `materials.transitions[]`.
- `add-transition` command — must insert the ref ONLY on the outgoing segment.
- `remove-transition` — must drop the ref AND clean the orphaned material.
- Validate that `loudnesses[]` ref is absent in this CapCut 169 capture
  (it appears in cutcli output but newer UI omits it).

### `masks-filters-draft.json` — Circle mask + Vintage filter @ 50

| | |
|---|---|
| **Size** | 20 kb |
| **Duration** | 5 s |
| **CapCut version** | 169.0.0 |
| **Tracks** | 1 video, 1 **filter** |
| **Materials** | 1 video, 1 `common_mask` (Circle), 1 `effects` (Vintage, value=0.5) |
| **Features** | `materials.common_mask[]`, `materials.effects[]`, `"filter"` track type |

A 5-second capture used to resolve Q3 + Q4. One image clip with:

- a **Circle mask** in `materials.common_mask[]` with full `config` block
  (`width: 0.5, height: 0.28, centerX: 0, centerY: 0, feather: 0, expansion: 0,
  invert: false, aspectRatio: 1.0`). Bound at `extra_material_refs[2]` (same
  slot as transitions — polymorphic) plus segment flag `enable_video_mask: true`.
- a **Vintage filter** in `materials.effects[]` at UI intensity 50, which
  encodes to JSON as `value: 0.5` — confirming filter intensity is in
  `[0, 1]` (slider/100). Lives on its own `"filter"`-typed track (6th track
  type — distinct from `"effect"`).

Test cases:

- Mask `config` round-trip — every field must survive parse+write.
- `resource_type` shape token (`"circle"` here; full set: `linear|mirror|circle|rectangle|star|heart`).
- Filter `value` math — never multiply/divide by 100 when reading or writing.
- The CapCut-UI vs cutcli filter split: UI filters go to `materials.effects[]` +
  `"filter"` track; cutcli filters go to `materials.video_effects[]` + `"effect"` track.
- `apply_target_type` enum: `0` = segment-local, `2` = global/track-wide.
